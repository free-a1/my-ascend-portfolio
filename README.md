## 四、重点成果

1. **Linux 基础链路打通**：目录规划 → 用户与权限 → 免密 SSH → 后台守护任务，产出 `init_env.sh` 一键初始化脚本（幂等、发行版代号自动探测）。
2. **日志分析与自动化**：用 grep/sed/awk 解析推理日志，产出平均精度 0.9175、平均耗时 44.00ms 的指标报表。
3. **Python 数据处理闭环**：数据集分类与重命名 → 标注清单 CSV/JSON → 推理结果 JSON → 报表（含低分框过滤与脏数据处理）。
4. **完整的 Docker 实践**（真实 Docker，非 unshare 替代）：镜像与加速器 → 容器生命周期与 exec → 三版 Dockerfile（CMD/ENTRYPOINT/多阶段）→ 数据卷持久化 → 自定义网络多容器互联 → docker-compose 编排示例。
5. **推理服务交付**：极简 HTTP 推理接口（8080）与 Flask 交付包（`/health` + `/predict`），含 curl 验收用例与部署说明。
6. **迷你 CV 推理**：自建 PPM 数据集 → 训练颜色质心 → 推理分类，记录置信度与耗时（0.02~0.03ms）。
7. **资源监控与异构计算**：`nvidia-smi`/系统命令采样 CPU/内存/磁盘/GPU，输出资源报表 CSV；无 GPU 时自动降级 NA。
8. **端到端交付与作品集打包**：交付包一键构建验收；作品集核验、Git 仓库打包（bundle）与压缩包输出。

## 五、踩过的坑与修复（真实记录）

1. **换源写死发行版代号**：模板脚本把 apt 源写死为 `jammy`，与本机 `resolute` 不符；且 Ubuntu 24.04+ 官方源为 deb822 格式（`ubuntu.sources`），只改 `sources.list` 会两套源混用。→ 改为从 `/etc/os-release` 自动探测代号，并禁用 deb822 源。
2. **容器内 DNS 解析失败**：`docker build` 内 `pip install` 报 `Temporary failure in name resolution`。→ 改用 `docker build --network=host` 复用宿主机网络。
3. **`-d -it` 保活不可靠**：自动化场景没有 TTY，容器会立刻退出。→ 改为 `sleep infinity` 保活。
4. **PyTorch 镜像过重**：`pytorch/pytorch:latest` 数 GB，拉取耗时不现实。→ 换 `python:3.11-slim`，张量前向计算用纯 Python 等价改写，并在文档中明确注明。
5. **路径硬编码**：脚本写死 `/home/ubuntu`、`/home/user/project/data`，换机器即崩。→ 统一改为 `$HOME` / `Path.home()`，并支持 `PROJ_DATA` 环境变量覆盖。
6. **Python 版本差异**：`X | None` 联合类型语法在 3.6/3.8 上直接报错，说明旧版本叙事不可行；本机用 3.14 正常。
7. **WPS 旧版 `.doc` 自动化**：Word COM 打开可写 `.doc` 会弹「是否转换」模态框导致自动化挂起，保存为旧格式也会弹兼容提示。→ 打开时传 `ConfirmConversions=$false`，保存改为原地 `Save()` 保持 `.doc` 格式。
8. **截图可信性问题**：早期屏幕区域截取会被其他窗口（甚至全屏视频）覆盖，甚至截到无关内容。→ 截屏管线改为 **PrintWindow 自绘窗口**方式（不受遮挡、不会截到桌面其他内容），并逐张人工核验非黑屏。
